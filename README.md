# 문턱

> 일을 더 하기 전에, 내 지원이 끊기는 **문턱**을 먼저 확인하세요.

청년이 알바·프리랜서 일자리 제안을 받았을 때, 그 일이 **부모 연말정산 부양가족 공제**, **건강보험 피부양자 자격**, **구직촉진수당**, **주 15시간 기준(주휴수당·4대보험)** 에 어떤 영향을 주는지 한 번에 계산해 주는 서비스입니다. 단순히 기준선을 넘는지만 알려주지 않고, 지원 감소까지 반영한 **실질 순소득**으로 더 유리한 근무 조건을 함께 제안합니다.

## 왜 필요한가

- 제도마다 소득의 정의, 인정되는 소득 유형, 산정 기간, 기준선이 모두 다릅니다.
- 그래서 청년이 "얼마까지 벌어도 되는지" 직접 판단하기 어렵습니다.
- 월소득만 비교하면 기준선을 넘는 시점이나 지원 감소를 놓치기 쉽습니다. 그 결과 일을 더 했는데 실제 순소득이 줄거나, 신고 의무와 자격 변동을 뒤늦게 알게 됩니다.

## 어떻게 동작하나

1. **일자리 조건 입력**: 공고 사진을 올리거나, 공고·제안 메시지를 붙여넣거나, 직접 입력합니다. AI가 시급, 근무시간, 기간, 소득 종류 후보(근로·일용근로·사업소득 3.3%·모름)를 추출합니다.
2. **추가 질문**: 모호하거나 빠진 조건은 한 번에 하나씩 되묻습니다.
3. **내 상황 입력**: 만 나이, 구직촉진수당 수급 여부, 부모의 피부양자·부양가족 여부, 올해 소득, 부모 연 소득 구간을 입력합니다.
4. **기준선 계산**: AI가 아니라 **코드**가 검증된 규칙표를 참조해 제도별 기준선 초과 여부, 예상 시점, 실질 순소득을 계산합니다.
5. **대안 비교**: AI 에이전트가 규칙 계산을 반복 호출해 아래 대안을 찾습니다.
   - 기준선을 넘지 않는 최대 근무시간
   - 기준선을 넘어도 총수입이 늘어나는 조건

   고용주에게 보낼 근무시간 조정 요청 문구도 함께 제공합니다.
6. **근거와 다음 행동**: 근거 조문, 적용 연도, 확인일, 신고 의무, 공식 문의처를 안내합니다.

## 핵심 원칙

- **AI는 추출·질문·설명만 담당합니다.** 기준선 판정과 금액 계산은 코드가 하며, AI가 계산값을 바꾸지 않습니다.
- **규칙표는 코드와 분리된 데이터 파일로 관리합니다.** 규칙마다 근거 조문, 적용 연도, 확인일, 상태를 기록하고 기대값 테스트를 둡니다.
- **원문이 확인된 제도만 계산합니다.** 근로장려금·실업급여·훈련장려금은 확대 후보입니다. 원문을 확인하기 전에는 계산하지 않고 "확인 필요"로만 표시합니다.
- **개인정보를 서버에 저장하지 않습니다.** 입력값과 내 기록은 브라우저 안에만 둡니다.
- **신고 회피 방법은 안내하지 않습니다.** 결과 하단에는 항상 아래 두 고지를 표시합니다.
  - "참고용 계산이며 세무·법률 자문과 행정기관의 최종 판단을 대체하지 않습니다"
  - "AI가 생성한 내용이 포함되어 있습니다"

## 주요 기능 (요구사항)

| ID | 기능 | 중요도 |
|---|---|---|
| REQ-001 | 일자리 조건 입력과 정보 확인 (사진·붙여넣기·직접 입력, 가상 샘플 3종) | 높음 |
| REQ-002 | 개인 및 제도 수급 조건 확인 | 높음 |
| REQ-003 | 공식 규칙 기반 기준선과 금액 계산 | 높음 |
| REQ-004 | 근무 조건 대안 비교와 추천 | 높음 |
| REQ-005 | 근거와 규칙 버전 관리 (현행·개정안 병기) | 높음 |
| REQ-006 | 결과 설명과 다음 행동 안내 | 높음 |
| REQ-007 | 품질 검증 (추출·소득 종류 판별 정확도 평가) | 중간 |
| REQ-008 | AI 호출 장애 대응 (재시도, 가상 샘플 결과 보기) | 높음 |

## 타겟 사용자

알바나 프리랜서 일을 추가하려는 청년이 대상입니다. 특히 아래에 해당하는 청년이 주요 사용자입니다.

- 구직촉진수당을 받는 청년
- 부모의 연말정산 부양가족이거나 건강보험 피부양자인 청년
- 소득 제약을 확인하려는 일반 청년 근로자

스마트폰을 우선으로 하고, 컴퓨터 웹 브라우저도 지원합니다.

## 핵심 지표 (목표)

| 지표 | 목표 |
|---|---|
| 조건 추출 완료율 | 80% 이상 |
| 추가 질문을 거친 뒤 계산을 완료하는 비율 | 70% 이상 |
| 계산 가능한 사례에서 기준선 초과 여부와 예상 시점을 확인하는 비율 | 90% 이상 |
| 근거, 적용 연도, 확인일, 상태가 표시되는 비율 | 100% |
| 근무 조건 대안을 비교하고 다음 행동을 확인하는 비율 | 60% 이상 |
| 계산 보류 사례에서 사유, 문의처, 신고 의무 안내가 누락되지 않는 비율 | 100% |

## 실행

```bash
python3 -m http.server 8770 --directory munteok
```

- 앱: http://localhost:8770/
- 규칙 엔진 테스트: http://localhost:8770/tests/

## 와이어프레임

와이어프레임은 수정 전 유저플로우(17화면) 기준입니다. 최신 유저플로우는 화면을 11개로 줄였고, 안내·로딩·보류(09·10·12·13)는 별도 화면이 아니라 해당 화면 안의 상태로 표시합니다.

| # | 화면 | # | 화면 |
|---|---|---|---|
| 01 | 시작 | 10 | 기준선 계산 중 |
| 02 | 내 기록 | 11 | 결과 |
| 03 | 올리기 | 12 | 계산 보류 안내 |
| 04 | 추출 확인 | 13 | 지원 범위 외 안내 |
| 05 | 추가 질문 | 14 | 대안 비교 |
| 06 | 원문 대체 입력 안내 | 15 | 대안 상세 |
| 07 | 내 상황 | 16 | 근거와 다음 행동 |
| 08 | 입력 요약 확인 | 17 | 근거 원문 상세 |
| 09 | 정보 부족 안내 | | |
